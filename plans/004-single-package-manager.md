## Why this matters

The repo ships two lockfiles for one `package.json`, and they disagree:
`package-lock.json` tracks the full declared set (9 hits for `lodash-es` /
`@tanstack/react-router`) while `pnpm-lock.yaml` has 0 — so pnpm installs are
stale/incomplete, yet `README.md:8-13` tells contributors to run
`pnpm install/dev/build`. One canonical manager ends the split-brain installs.

## Current state

- Root contains both `package-lock.json` (npm, lockfileVersion 3) and
  `pnpm-lock.yaml` (version 9) for the same `package.json` dependency set.
- `pnpm-lock.yaml` importer block omits `lodash-es` and `@tanstack/react-router`
  although `package.json` declares them (lines ~16, ~21) and `src/lib/utils.ts:2`
  imports lodash-es. `package-lock.json` tracks them.
- `README.md:5-13` documents `pnpm install`, `pnpm dev`, `pnpm build`,
  `pnpm lint`, `pnpm preview`.
- Decision (pre-made by evidence, not yours to revisit): **keep npm** — its
  lockfile is the complete one, and the project's verification history
  (`npm run lint/build`, `node scripts/*.mjs`) was all executed under npm.

**Verify**: all three commands exit 0. `npm ls lodash-es @tanstack/react-router` → both resolve (proves the kept lockfile covers the full declared set).
